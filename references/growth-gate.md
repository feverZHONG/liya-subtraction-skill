# 进出门规则 —— 新 skill 怎么进来、老的怎么出去

> 2026-09-26 阁下问「在想着有必要整 109 个 skill？」之后立的门。
> 一句话：**数量本身不是问题（109 个里 107 个真被调用过），成本在预载索引（约 7000 字符 description／轮）与「同族各占一个触发位」。**
> 所以不靠「定期大砍」，靠两道门：**进来时先问三句，出去时按四条判据**，中间每季度对一次账。

## 一、进：建 skill 之前先问三句

1. **能不能并进现有 skill？**（同域先找宿主——同站点、同一动作、同一产出的，先翻库）
2. **能不能只做它的 `references/`？**（单个子场景、一份细节档，挂到宿主下就够，不必独立触发位）
3. **触发场景真的与现有 skill 不同吗？**（同一句话会不会同时命中两个 → 那叫重复，不叫分工）

三句里任何一句答「能」→ **不建新 skill**，改写宿主的 SKILL.md／加一份 reference。

**反例（都是实证）**：同站点两份（`wufan-extractor` × `wufan-forum`）、同一动作三份（`legacy-draft-mining` × `draft-archaeology` × corpus-line-mining 里的 legacy-draft-cards 档）——都是没问这三句造出来的，2026-09-25 一次性并掉。
**并行会话**：建 skill / 改共享文件**前先查一遍库**（同日撞过车，造出过功能重复的 skill）。

## 二、出：季度对账（一条命令 + 四条判据）

```bash
python3 skills/skill-curation/scripts/skill_retire_scan.py --days 60
# 按「最后调用距今天数」出表：最后调用 / 天数 / 次数 / 体积 / 有无脚本 / 台账 state
# 零调用但创建不满 30 天的单独分组（新 skill 还没轮到场景，不算候选）
```

**四条判据——命中任何一条一律保留，零调用 ≠ 无用：**

| 类 | 说明 | 例 |
|:--|:--|:--|
| **档案库／资料库** | 数据资产，触发了才读 references | （私档）-archive、（私档）-archive、enneagram-notes |
| **内容型** | 笔记、数值库、原创连载 | video-editing-course、gbf-relink、（私档）-crusaders |
| **勿忘类** | 存在价值不是「常被调用」，是不该被忘掉 | history-archive（阁下：「勿忘历史」） |
| **季节性** | 一年只用几个月 | typhoon-monitor、chinese-convention-search |
| **工具手册（带脚本）** | 删了工具就没入口，下次还得重写 | debug、douyin、nga-extractor |

**真候选** ＝ 连续 60 天零调用 **且** 不在上表五类 **且** 内容已被别处覆盖（判「覆盖」用判据指纹，见下节）。
**候选清单只交给阁下垂裁**——本流程不做自动删除；降级选项优先于删除（脚本/git mv 到 `workspace/scripts/`，经验压进 `workspace/memory/*-experience.md`）。

## 三、合并必同步（阁下 2026-09-26 立的规矩）

> 原话：「**即便是方案一整合并，也要同步更新 skill 才行。**」

合并 ≠ 把触发位并掉就完事。**七件套，缺一样就是假合并：**

1. **宿主正文吸收**——独有内容按主题归位、**逐字搬**（不重写、不缩写），搬完在档头注「YYYY-MM-DD 从 X 并入」；
2. **被并方 `scripts/` 先接管**——被正文引用着的工具脚本（`dialog-ratio.py`／`wufan.py` 这类）不迁就断链；
3. **CLI／wrapper 改指 + 实测跑一次**——`bin/*` 里的硬路径要改，改完**拿真数据跑一遍**才算过；
4. **全局 grep 残留引用改指**——跨 skill 引用要扫全库（别只看宿主目录）；
5. **台账 `.usage.json` 标 `archived`**（note 写明并到哪儿，否则下轮 audit 当 ghost）；
6. **下游索引同步**——发布候选表去行、表内数字列（skill-publishing 的 publish-candidates）、库内 INDEX／README 的指路行；
7. **收尾四件**——布局扫（无嵌套）／跨 skill 相同长行／`bin/mdcheck` **对基线**（涨了就是欠账）／相对指涉复核（「见上／见下」搬完会失锚）。

最后记一笔 `pruning-history.md`（哪一轮、并了谁、数字、教训）。

**将来做「同族合并」（B站系、提取器系）时，这条是前置条件**——先备齐七件套再动手，别只把 description 缩掉。

## 四、判「独有内容」用判据指纹，别用整行匹配

两份同义改写的 skill，整行比对会**假报大片「未覆盖」**（2026-09-25 实证：67 行里假报 60 行，其实大半早写在别处、只是措辞不同）。
正确做法：把**专有概念词逐个 `in` 全文**（`情绪核`／`去容器`／`身份一致性`…）——数到全中才算搬完；命中率全高＝内容已被宿主吸收，只搬余下的实测数字／命令细节；命中率半数以下＝整档搬成新 reference。

同理，**同主题的两份 skill 用机器根本查不出来**（逐字长行可能 0 条、8-gram 相似度 <0.02）——只能按名点读全文，人工判。
