# 核心原则

1. **不信任描述，读全文** — `skill_view` 读 SKILL.md 正文才能发现真重叠。描述字段可能误导。
2. **脚本化是第一优化** — 5 步以上的顺序操作封装成可执行脚本，SKILL.md 缩成 CLI 参考 + 关键规则。
3. **三件套分层** — 脚本按职责分三层，不混在一处：
   - **py** — 数据处理、计算逻辑、文件读写。厚逻辑层。
   - **ts** — 可视化、交互界面、网页/客户端。薄视图层。
   - **cli** — 自动化、守护、管道联动、通知。胶水层。
   - 一层的事不在另一层做。py 不画界面，ts 不写文件，cli 不重复计算。
4. **批量提案，一次确认** — 同类操作分组（确定能删的/可合并的/需确认的），让用户一次性做决定。
5. **减法公式 / SKILL.md 总入口化** — SKILL.md 只写「这是什么 + 什么时候用 + 怎么用（速记）+ 指向 references 的索引表」，不内嵌详细说明。**能拆就拆：SKILL.md 里的任何详细内容（流程细节/长规则/踩坑/模板/代码示例）默认拆到 references/，包括已经写好的说明 md**。2026-08-06 全库验证：21 个厚 SKILL.md（95-240 行）→ 12 个拆薄 + 9 个判定合理保留（数据索引/高频主场景/方法手册），全部保持「入口+引用」结构。判断标准：**主场景高频内容留 SKILL.md（每次都要读的），子场景细节拆 references/（用到才读的）**；导视表/索引/题库等数据类不算内容，保留在 SKILL.md 或独立目录。
6. **方法论文档例外** — `tech-workflow`、`skill-curation` 这类思路性经验性内容保留详细说明，没法脚本化。
