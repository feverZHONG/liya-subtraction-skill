# 技能用途审查

缩完 SKILL.md、测完 API 后，追问一个问题：

**「这技能真的有实际用途吗？」**

不是「能不能跑」，是「谁会主动用它」。如果答案是「大概没人会主动调」：
- 方法论类 → 吸收入 `tech-workflow` 或 `writing-standards` 作为参考节
- 玩具类 → 直接删除，不保留存档
- 信息类 → 问问自己：有没有人值得记住这些事？

## 空壳目录识别

不是所有 `skills/` 下的目录都是真技能。

| 形态 | 特征 | 处理 |
|:-----|:------|:-----|
| **仅 DESCRIPTION.md** | 目录下只有 DESCRIPTION.md，无 SKILL.md | `rm -rf` 直接删 |
| **skill_view 返回 404** | 找不到对应名称 | 同样是空壳，`rm -rf` |
| **「留待将来」占位** | 写「xx功能待添加」或无实际指令 | 删 |

判断方法：`skill_view(name)` 返回报错 → 即空壳。`ls -la skills/<dir>/` 确认只有 DESCRIPTION.md → 即空壳。`rm -rf skills/<dir>/` 清除目录。

## 暂存待决模式

```bash
mkdir -p /opt/data/temp
rm -rf /opt/data/skills/<target>          # 确定要删的
mv /opt/data/workspace/<target> /opt/data/temp/  # 拿不准的
```

不确定是否保留的技能 → 移入 `temp/` 而不是直接删。等用户确认后再决定去留。

**记录为什么移：** 在 `temp/why/` 下写一个说明文件。比靠记忆恢复快得多。

## ⚠️ 「有没有用」的判断陷阱

不要把「有没有实用价值」和「值不值得保留」划等号。

**实例：** `on-this-day`（历史上的今天）。本天使最初判定「维基不可达 + 无人会翻 → 建议删除」。用户回了四个字：「勿忘历史」。

有些技能的存在价值不是「每天有人调」，而是**有些东西不该被忘记。**
