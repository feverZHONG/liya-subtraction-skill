## Description 精简（本轮新发现）

Description 字段是 Hermes 匹配 skill 的唯一入口。过长的描述浪费 token 且降低匹配精度。

### 精简原则

| 原则 | 说明 |
|------|------|
| **一句话** | 不超过 30 字，说清楚做什么 |
| **不要堆关键词** | `diary-writer` 原来有「日记、日記、diary、daily log、memory记录」→ 删 |
| **不要教 LLM 什么时候用** | `docx` 原来写 20 行「whenever...triggers include...」→ 删，LLM 知道 |
| **不要说明书** | `music-download` 原来写「TV-size/Full Size 识别、去重、花名册」→ 一行搞定 |
| **不要 `|` 多行 YAML** | `xbrowser` 和 `humanizer-zh` 原来用 `|` 块 → 压成一行 |
| **全中文** | `bilibili-dl`/`img-vision` 原来英文 → 统一中文 |

### 精简测试

description 修改后不需要 reload：Hermes 下次匹配时自动读更新后的 frontmatter。

### 实际效果（本 session）

21 个 skill 的 description 从平均 60 字压到 15 字。总字数从 ~1260 字降到 ~315 字，减 75%。

### 2026-10-07 全库实测：三类真正可动的

扫描 106 个（合计 7149 字符、中位 56）后，能动的只有三类——**大部分描述已经到位，别再对它们动刀**：

| 类型 | 判据 | 实测 |
|:--|:--|:--|
| **塞了状态/统计** | 「已收录：…」「全量 N 条」——那是给正文看的，不占每轮注入 | rimworld-text-archive 190→112、icey-archive 185→113（各 -70 上下） |
| **教学句/工作流罗列** | 「当用户需要…时使用」「工作流：A→B→C」 | dialogue-system-builder 232→92（**-140**）、subtitle-proofreading 200→146 |
| **`Use when` 英文开头** | 前 57 字符窗口被 8 字符英文模板白占 | 6 个全改中文开头；长度持平或更短、窗口内多出一整段有效词 |

**反面：窄描述要补、不属减法**——`hermes-plugin-authoring` 原描述只有「写/装插件」一句，改时顺手把「插件契约／验证三件套／现成实例」补回去（37→45，**加长是对的**）。

**改完必跑两个自查**：① frontmatter 用 `yaml.safe_load` 解一遍（描述里带引号／`:` 会弄坏 YAML）；② **关键触发词逐个 `in` 抽查**（能力名、CLI 名、场景词一个不能丢——这是 2026-08-24 柿崎惠那笔血账的机械版）。


### 57 字符窗口的两条用法（2026-10-07 点出）

索引只显示前 57 字符——这既是**约束**也是**判据**：

1. **前 57 是精选位**——必须装「能力名 ＋ 最高频触发词」，**别让半句模板或半个词占位**（实测 `hermes-gateway-ops` 原有尾巴截在 `（结论+退出码 0/1/2` 上，半个括号）。改完逐个看前 57，确认高频入口都在。
2. **57 之后只装「装不下的额外触发词」**——**说明句、操作步骤、导航指针一律搬正文**（`→ skill: novel-writing` 这类导航、`分模块详见各 .md 文件` 这类交代：扫列表看不见，加载时正文又有）。

⚠️ **别把「超出 57」一律当浪费**：全库 50 个超出的，其中 **40 个的超出部分就是必要触发词**（`bilibili-api-ops` 的「热搜榜、字幕、cv号、B站文章、接口坑…」、`voice-output` 的「换音色、查额度、克隆音色…」）——删了就是 2026-08-24 那笔血账。真正的「说明型尾巴」只有 **10 个**。

### 精简要有度（2026-08-24 教训）⚠️

**精简过头 = 工具找不到。** 描述是匹配入口，压到只剩「做什么」而删掉「触发词」，扫列表时不知道这个 skill 能解决当前问题，工具躺在那被忽略。

- **柿崎惠查证翻车实录**：read-url 描述只写「网页正文净化器」→ 想不到它能读百度百科（wapbaike 降级 08-16 就内置）；bilibili-api-ops 描述只写「热搜/字幕」→ 想不到它能查专栏文章。四个卡点三个有现成工具没用上。
- **57 字符窗口**：Hermes 技能索引只显示 description 前 57 字符。核心触发词（能力名+场景词）必须在前 57 字符内命中，否则扫列表看不到。
- **触发词怎么放**：`能力名（脚本名/命令名）+ 场景触发词`。例：`B站接口查询——热搜推送/CC字幕/专栏文章搜索直读(bili_article)/番剧分集/视频详情。触发：热搜榜、字幕、cv号、B站文章、接口坑。`
- **新工具建档同步补**：新增脚本/新能力（如 bili_article.py、bin/baike）时，description 必须同步更新——skill 正文写再多，索引不标就等于没有。
- **体检**：描述明显短于 references/scripts/ 实际能力的，属于「窄描述」，要补（2026-08-24 已补 8 个：read-url/bilibili-api-ops/chinese-news-aggregator/info-hunt/news-verification/hermes-agent/taobao-affiliate/documents）。
