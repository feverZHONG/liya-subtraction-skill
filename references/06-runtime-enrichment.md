# 运行时技能富集（增量反馈 → 规则沉淀）

精简维护之外的另一条技能进化路径：**正在使用的 skill 在 session 中被用户反馈不断修正和丰富。**

## 模式识别信号

| 信号 | 动作 |
|:-----|:------|
| 用户发了一条纠正 | 立即在相关 skill 中新增/修正对应规则 |
| 用户发了一个截图/反馈 | 提炼成可复用的规则模式 |
| 你说「记下了」但没写进 skill | 等于没记。用户教的每一条都要落地到文件 |
| 同一类反馈出现两次 | 说明规则没写够细，补 |

## 实例（2026-07-10 · 谁是卧底词库）

```
用户输入→「一轮不能盘出双边」
         → 牢八截图: 「全员天使环节」「没有百科」
         → 规则黑板照片验证
```

**沉淀到 skill 的内容：**
- 好题第一性原理：一轮不能盘出双边
- 好题第四要素：可描述性
- 直播间术语对照表
- 常见失败模式分类（从已移除数据反推）
- 玩家反馈信号表

## 原则

1. 用户说的每一条纠正，落地到 skill 文件，不只是 memory。Memory 记「这个用户喜欢什么」；Skill 记「这类任务应该怎么做」。
2. 先录规则，再考虑是否要重构。碎片规则可以先追加，等有足够量了再统一整理。
3. 同一 session 内补完。用户给了反馈，当场改完，不要等「下次再说」。

## 技能维护收尾四查（改完 skill 必查，2026-08-26 定）

任何 skill 改动收尾前过四道，漏一道下次就找不到/不同步：

1. **SKILL.md 文档同步** — 改了 scripts/references/结构，SKILL.md 里的说明/路由/清单跟着改
2. **frontmatter description 同步** — 前 57 字是触发窗口（08-24 定规矩、08-26 再犯 team_query 后收进四查）；写完看 description 有没有提到新东西
3. **INDEX/入口更新** — skill 根 INDEX.md、相关入口 skill 的引用行同步
4. **git 提交** — 当场 add + commit，不攒批
