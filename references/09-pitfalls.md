# 踩坑记录

0. **`bin/mdcheck` 的「引用不存在」会误报说明文字里的裸文件名** — 它把反引号里的裸文件名当链接解析，所以**说明文字里列举的文件名**（SKILL.md 表格中「`skills/sugar-frosting-crusaders/references/relationship-web.md`：检查新角色…」、篇目录示例「「article.md」 ＋ 「逻辑链.md」」）一律被报断链。实测糖霜 skill 报 16 处、真断链只有 2 处（跨 skill 引用没写清是哪个 skill 的）。**判读先看路径**：带 `references/` 或跨 skill 前缀的才是真链，裸文件名＋说明文字＝合理误报，别去改文件。

1. **absorbed_into 不搬文件** — `skill_manage(action='delete', absorbed_into='X')` 只记录元数据关系，不移动脚本。手动拷贝。
2. **同名技能不一定真重复** — 不同天使可能有同名但内容不同的 skill，读全文判断，不能简单覆盖。
3. **空壳目录没有 SKILL.md** — `diagramming`、`domain`、`feeds` 等只是分类占位，`skill_manage(action='delete')` 找不到它们，必须 `rm -rf` 从文件系统删。
4. **超过 70 行的方法论文档例外** — `tech-workflow`(465行)、`skill-curation` 这类是思路性内容，没法脚本化，合理保留。
5. **凭描述做决策撞过车** — `web-search` 和 `global-search` 描述都写「搜索」，读完全文才发现完全一样。必须读全文。
6. **confirmed-unused 不等于 skill_manage-deletable** — 确认无用的 skill（有 SKILL.md）可通过 `skill_manage(action='delete')` 正常删除。但只有 DESCRIPTION.md 无 SKILL.md 的空壳必须 `rm -rf`。
7. **删技能前先列出清单给用户确认** — 批量删除前先列举分组，让用户一次性过目。拿不准的先移 temp/。
8. **一轮清理不够** — 大合并+移temp 之后重新审视列表再做一轮。第二轮会发现薄技能吸收的机会。
9. **temp/ 要加 gitignore** — 从 gitignored 的目录移技能到 temp/ 时，如果 temp/ 本身不在 gitignore 中，这些文件反而从「被忽略」变成了「可追踪」。
10. **类别目录会把 skill 挤出预载索引** — `system/voice-output/` 这种类别嵌套会让 skill 在系统提示的预载索引中不可见。所有 skill 必须平铺在 `skills/` 根目录，不要套类别文件夹。
11. **一个 skill 里不能叠另一个 skill** — `skill/references/` `skill/scripts/` 只能放内容文件和脚本，不能放另一个完整的 skill 结构（即不能有 SKILL.md）。违反这条会导致：
    - 子 skill 被隐藏在父 skill 目录下，永远进不了预载索引
    - `skills_list` 可能扫不到（取决于深度）
    - 维护时容易误删或漏迁
    - 正确做法：每个 skill 独立一个目录，references/ 下只放 .md 文档
12. **游离脚本归位前先查 cron 软链依赖（2026-08-05）** — SKILL.md 里写 `python3 workspace/scripts/xxx.py` 而 skill 下无 `scripts/` = 脚本没归位。但 `workspace/scripts/` 的脚本可能是 cron 硬依赖：数据根的 `scripts/` 下常有软链指向它（如 `bili_hot_push.py`、`patch_qqbot_send_target.py`），cron wrapper（no_agent script 字段）经软链调用。归位动作：`git mv` 保留历史 → 同步改 SKILL.md 引用 → **检查数据根 `scripts/` 下的软链并重新指向新位置** → 语法验证 `python3 -m py_compile` → 全库 grep 残留引用。判别：被 cron wrapper/`sys.path.insert` 硬编码依赖的脚本（如 `qq_group_roster.py` 被 `qq_group_sync_cron.py` import）留原地，skill 引用保持绝对路径。
13. **死引用标注「不可直接运行」而不是改指别处（2026-08-05）** — location references 引用了已删除的 `weather_cn.py`（fetch/parse_alarms/CITY_ID 接口已不存在），先试着改指 `weather_report.py` 但该脚本没有这些函数——改错。正确做法：确认原接口彻底消失后，在文件顶部标注「历史参考，不可直接运行」+ 给出当前可用命令，代码块保留原文。改引用前必须验证目标脚本确实提供被调用的接口。
14. **双向同步的完成判据看文件标记，不看 index 状态（2026-09-13）** — 冲突是否解决要检查文件里还有没有 `<<<<<<<`，不能用 `git diff --diff-filter=U`：未合并记录在 `git add` 之前一直在，标记被人手改干净了也照样报「没改完」。同类：`git status --porcelain` 报的是 index 状态，不是内容对错。
15. **并行会话会造出重复 skill（2026-09-18）** — 多个 hermes 会话同时在同一个案子上干活时，两边各自建了功能相同的 skill（`draft-salvage` vs `draft-archaeology`，相隔一分钟）。判别与处理：① 建 skill / 改共享文件**前先查一遍库**；② 撞车时不按新旧、**按完整度留**（本次留下的那份 references 更全、且已引用本案档案）；③ 把另一份里的**独有部分并过去**（收编了工具 `score.py` + 一份确认清单）再删重复；④ 合并后**统一两份之间不一致的参数**（脚本判据阈值与 references 不同 → 以更严的那份为准），并实测跑一遍拿数字。
16. **skill_manage patch 被「frontmatter YAML」拦下时，先修 description 里的裸冒号（2026-09-21）** — 报错写「Patch would break SKILL.md structure: YAML frontmatter parse error: mapping values are not allowed here」，看着像本次改动的问题，实际是**文件里早就存在的**：`description` 里出现 `: `（典型是 `skill: novel-writing` 这类引用写法）＝YAML 裸标量带冒号，本身非法；校验只在 patch 时跑，所以一直没拦到。判别：报错行号指着**前几行的 frontmatter**、不是刚改的段落。做法：**同一批 operations 里顺手把 description 用双引号包起来**（`description: "…"`）即可过，别去改 body。另：patch 会抹掉文件开头的 BOM，无害。
16. **改路径引用别只 grep 字符串形态（2026-09-22 平铺实战）** — 把 `knowledge/`、`writing/` 里的 8 个 skill 提平到顶层时，`grep "skills/writing/x/"` 抓到 26 处并全改了，但漏了**拼接式**的引用 `ROOT / "skills" / "writing" / "x"`（`<项目>/scripts/story.py:369`）——它是几个独立字符串，正则和字符串替换都碰不到，直到 pre-commit 门禁跑挂才暴露。
    规矩：**改完路径要把那几个脚本真的跑一遍**（或对每个路径段单独 grep 一次），别只信「引用全改完了」；门禁拦下来是运气好，拦不下来的会变成下次才炸的坑。
17. **同主题两个 skill 用机器查不出来（2026-09-25）** — 两种机械手段都失效：① 跨 skill 逐字长行比对（同站点两个 skill 的「共同长行」可能是 0 条）② 8-gram Jaccard 全库相似度（只有共享模板的档案库群能到 0.10+，其余同主题对全在 0.02 以下）。这类重复只能**按名点读全文**：同一站点／同一动作／同一产出的名字摆在一起人工判——实例 `wufan-extractor`×`wufan-forum`（同站点）、`legacy-draft-mining`×`draft-archaeology`×「corpus-line-mining/references/legacy-draft-cards.md」（三处同一动作）。
    判「哪些内容是独有的」也**别用整行匹配**——同义改写的两份会假报大片「未覆盖」（本次 legacy 67 行里假报 60 行），要按**判据指纹**查（把专有概念词逐个 `in` 全文：情绪核／去容器／身份一致性…）。
    合并四步：**宿主选被活引用最多的那个**（本次选 `wufan-forum`，它有跨 skill 活引用且在发布候选表里）→ **scripts 先接管再删**（被正文引用着的工具脚本不迁就断链）→ **CLI/wrapper 改指后实测跑一次**（拿回真数据才算过）→ 收尾拿基线目录前后对比 mdcheck（搬进的新文本常欠新账，如泛指 「INDEX.md」 带反引号被当路径）。
18. **移档了但没提交删除 → 每日文字存档整包失败（2026-09-27 实炸）** — 09-26 三批精简把 `bili-manga-download`／`chinese-convention-search`／`storytelling-review` 移进 `skills/.archive/`，磁盘上没了、**git 索引里还在**（`git status` 显示 ` D` 未 stage）。后果不是「少备份几个文件」：`scripts/backup_text.py` 按 `git ls-files` 取文件，`tar.add` 碰到不存在路径直接抛 `Errno 2` → **当天 15k 文件的文字包一个都没打成**（cron 报 error 才发现）。自查命令与修法见 `02-curation-workflow.md` Step 7。**连带教训：断头软链同样触发**——skill 目录重组后 `bin/xxx -> skills/旧路径` 变成死链，`os.path.exists` 也是 False（本次同批查出 `bin/draft-score`、`bin/mmx-quota` 两条）。所以「移档收尾」的判据是 **`git ls-files` 与磁盘逐条对得上**，不是「磁盘上没有残留」。**查/修一条命令：`bin/tidy index` ｜ `bin/tidy index --fix`（2026-10-04 收进 CLI）。**

19. **`sk verify` 守恒校验会拦下 SKILL.md 里合法的跨引用改动（2026-10-06 实测）** — 减法时顺手改了 SKILL.md 里一处节号指针（§五→§四，跟着 reference 的重编号走），守恒复核立刻报一条 MISS（就是那行）。它比的是**基线 SKILL.md 每一行**是否仍出现在「新 SKILL ∪ refs」里——**任何改动（哪怕一个字符）都算缺**，只有纯搬运／纯删除才过得去。解法：**能不动 SKILL.md 就不动**——本次把 reference 里两节换位（拒绝原则 ⇄ 斜杠命令），节号自然升序，SKILL.md 回到零 diff，复跑「守恒缺失 0 ｜ mdcheck 2 → 2 ✅ 不欠账」。判据：SKILL.md 那行非动不可时，就把改动挪进 references。

20. **「去重」的净体量可能为正，别按重复段长度估（2026-10-06 实测）** — 预估 −800~1000 字符，实测 −67（去重）＋109（修口径）＝**净 +42**。两个原因：① 重复只是**外壳**（三张表的级别标题 ＋ 三句做法话术），**独有内容夹在中间**（每张表的「例子」列、独有的那句 T0 话术）——能砍的只有壳；② 去重时撞见一条**作废口径**（旧文写「一句『私聊见』走人」，与 2026-09-22「群里拒绝不提私聊」冲突），修冲突是要加字的。**结论：减法的收益按「一处定义」的条数报，不按字数报。**要报字数先量：`wc -c` 是字节、`wc -m` 是字符，中文差三倍（实测一个 6232 字符的 SKILL.md，字节报 13551）。

21. **「一属性一档」型碎片库该合卷——判据看「中位体积 × 真实用量」，不看文件数（2026-10-16 萌属性实战）** — `enneagram-notes` 的萌属性判型卡 2184 个档，median **1.0KB**（frontmatter ＋ 萌娘一句话定义 ＋ 三个空壳占位节），而 49 个角色案例只命中其中 **298 个**（≥2 角色共有仅 77 个）＝**96.5% 从建档起从未被用到**；1KB 小文件每个还白占 4K 磁盘块，9.4M 里一多半是块空洞。合卷成 **139 个「叶组档」**（每个有属性档的小节 `## 属性名`）→ **2.2M**，信息守恒（2184 = Σ 小节，✅65 逐一对得上）。
    判据与粒度：**单档体积中位数 ≈ 1KB、且下游真实用量远小于存量 → 该合**；粒度取**「有直属档的目录」而不是「最小目录」**——中间层目录自己也可能带档（本次 139 = 130 纯叶组 + 9 中间层）。改造要点：**新扫卡层（属性 → 档＋锚点）放公共库让各 CLI 都走它**；**下游渲染器若读索引表，就把那张表的结构保住**——本次 INDEX 保留「属性级行」，于是 `moe-ls` 零改动、总览数字与迁移前逐项一致（数据源换了、结果不变，这是没伤到语义的力证）。

22. **迁移/回滚三板斧（2026-10-16 同一战）** —
    ① **`git checkout HEAD -- <path>` 不删未追踪的新产物**：回滚后上轮生成的文件还在盘上，重跑时被当成源叠了一层（156 档 / 2320 小节，一眼看出是「源里混了产物」）。口诀：**回滚＝`checkout` ＋ `git clean -fd`**，干净判据是「**磁盘文件数 == `git ls-files` 数**」（本次两边都 2186 才算干净；只数一类文件会漏）。
    ② **迁移只数文件守恒不够，要逐字段核对**：本次漏搬 frontmatter 的**消歧义全名**（`死神(种族)` / `死神(体质)` 合成了两个同名节，查档歧义）和正文的**官方分类字段**（下游 S6 核对直接报 0 档才发现）。**教训：字段清单从原始档里枚举一遍，迁移后逐个 grep 计数**。
    ③ **批改正则别把路径里的合法字符当分隔符**：`moe-props/([^、\s]+\.md)` 把顿号排除了，而大类名里就有顿号（`相貌、体型特征类`、`服装、饰品、着装状态类` 等 5 个）→ 整类路径静默漏改 24 处。补搜姿势：**改完再跑一遍「还剩哪些旧式路径」的扫描**，别只看第一批命中数。

23. **linter 的 `dangling-reference` 大多是尺子问题，别见报就改（2026-10-16 全库甄别）** — 它的规则是「正文里出现 `references/xxx` 字样且本 skill 内无此文件就报」，于是**正文写「见 `其他skill` 的 `references/x.md`」也会中招**；而跨 skill 引用本来是本库的常态。实测：65 条里——跨 skill（全库搜得到同名文件）**45**、模板/占位符（`YYYY-MM-DD`／`xxx`／`type-N`／`N-` 这类）**13**、其余特殊写法 7（泛指「翻 skill 的 references/API 文档」、历史说明「原 `references/x.md` 已并入」、目录树示意图、`../../workspace/...` 跨目录、`characters-api-*.json` 通配符），**真断链 0 条**。
    甄别三步（别一条条肉眼读）：① 模板/占位符正则先排掉；② 拿文件名在全库 `rglob` 一遍，别处有同名就是跨 skill；③ 剩下的才逐条看上下文。
    **但甄别的副产品值得收**：本次顺带查出 7 处真问题——①**假承诺**：SKILL.md 表格承诺了 `references/xxx.md`，文件从没落笔（git 历史里也查不到）；②**文件名写错/简称**：`references/子代理模板` vs 实存的 `skills/document-translation/references/subagent-prompt-template.md`、`04-画质策略` vs `skills/bili-archive/references/04-画质策略-优先级体系.md`；③**指向已不存在的文件**（内容早改由脚本承载）。修法：假承诺 → 如实标注或补内容；简称/错名 → 改全名；指向失效 → 改指真承载处。**git 查不到文件名历史 = 从没建过**（`git log --all --diff-filter=D -- '*x'` 空就是铁证）。

24. **硬编码数据根解耦：三类分开处置，别一刀切（2026-10-16 全库 136 脚本实战）** — 全库 148 个脚本写死绝对数据根、共 250 处。**三类处置完全不同**：
    ① **数据根下的相对路径**（`workspace/`、`cache/`、`downloads/`、`bin/`、`temp/`、`repos/`…）→ **该解耦**（`BASE + "/…"`）；
    ② **skill 自身路径**（`skills/<name>/…`）→ 用 `__file__` 上溯/探测；
    ③ **宿主环境**（`.venv/`、npm 全局目录、`secrets/`、`state.db`、浏览器缓存）→ **不碰**，留作外部依赖——硬套相对路径反而掩盖「发布后本来就没有」这个事实。
    统一 `_data_root()`：`$HERMES_ROOT` ＞ `$SKILL_ROOT` ＞ 脚本上溯 ＞ `~/.hermes` ＞ 家目录，判据＝该层下有 `skills/`。本库先例：`chat-game-referee`(6)/`sea-turtle-soup`(2)/`knowledge-persistence`。
    改造四步，缺一就翻车：**① 小样先行**（单 skill 试跑看 diff）→ **② 插入点用 `ast` 定位**，别用正则找 `^import`（会撞多行 import 的括号，实测插进括号里直接语法错；`ast` 解析失败的模板文件自动跳过）→ **③ 改完全量 `py_compile`**（本次 143 文件一次过，唯一失败的是本来就坏的 markdown 模板）→ **④ 假根演练**（把脚本复制进一个假 fakeroot 看它认不认——这才是「真解耦」的证据，光 py_compile 只证明语法对）。
    另：保护清单的正则别写成 `(A|B|C[^"']*)`——`[^"']*` 只作用于最后一条分支，前面的会漏保护（用非捕获组 `(?:A|B|C)`）。**改完必须复扫残余**：本次剩 4 处全是合理的（2 处是「已有探测＋兑底默认值」、1 处 docstring 示例、1 处不能解析的模板）。

25. **「查询键」要与库里「主键的形态」一致——否则静默误报（2026-10-16 moe 库）** — 那个库的主键是**全名**（`女王(性格)`、`空条承太郎`），下游却多处拿**短名**当查询键，两次都出事：① 案例侧的剥壳指纹词写短名「女王」→ 查档函数按消歧义规则（唯一候选还要求名称无括号）返回 None → plan 把 **10 个已完成的档全报成「🏗建档」，差点白建重复档**；② 新写的卡用简称「承太郎」→ 反向检查（案例角色有没有出现在卡里）认不出 → 报「缺案例」。
    **通用规则：一对多查询返回 None，必须分「真的没有」和「键形态不对」两种情况**——后者不报错、不说原因，只安静地说「缺」，最容易被后来的人当成事实照做（包括自己）。
    修法：① 查询函数分强度档（精确 → **唯一候选也算命中** → 多候选才 None），别让「防歧义」的保守规则吃掉唯一命中的正常情况；② 写内容时用**库里的主键形态**；③ 真歧义（2 个候选）才交人工。

26. **临时文件名要唯一——固定路径 + 下游文件缓存 = 静默串档（2026-10-16）** — 抓取降级链把 HTML 存成固定路径，而下游净化器带 5 分钟文件缓存 → 抓第二个词条时净化器直接回上一次的缓存 → **词条 A 的正文被写进了词条 B 的定义**（实测：`女儿控` 拿到 `后宫` 的定义）。
    通用：**固定临时路径 + 带缓存的下游 = 串档**；修法是临时名按输入取哈希唯一 + 显式 `--no-cache`。
    附带：**串档是静默的**（不报错、格式正常），只有看内容才认得出——批量抓取要么每个输入验一遍首句，要么从源头保证文件不重名。

27. **缺失 ≠ 冲突：审计口径里「取不到」要单列（2026-10-16）** — 审计脚本把「（未取到）」这类**抓取缺失**当成**分类冲突**报了出来（上游部分词条没有标准 infobox）。
    通用：**对账/审计类脚本，「取不到」和「取到了但不一致」是两种事**——前者是覆盖率问题、后者是正确性问题。混在一起报，既让人对着一堆假冲突麻木，也让「含字段 N 档」这种计数失真。修法：缺失单独计数并在输出里注明（本次：`含类别字段 1954 档全 OK；无 infobox 可核跳过 1 档（抓取缺失，非冲突）`）。

28. **已有文字标注的信息，不要再加一层结构化标记（2026-11-10 案例库分级标记评估）** — 「素材薄/只到嫌疑」这类信息已经写在三处：INDEX 定位列（17 处）、案例内文（5 档自标）、quickref（9 条带嫌疑）。再加「核心/参考/薄样本」字段就是第四份副本，改一次要同步四处；而且「多薄算薄」没有客观判据（对话 11 句算不算？），打标必漂。
    判据：**问「这三个字现在 grep 得到吗」——能，就别建结构**。真要区分，用现有字段过滤（`grep 素材薄`），零维护。等档数破百、或真出现「拿薄档当定论」的事故再建。
